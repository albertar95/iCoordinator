# Findings: یافته‌ها و ریسک‌ها

این فایل مشکلات شناخته‌شده، ریسک‌ها و نکته‌هایی است که هنگام نوشتن کد پیدا شد یا احتمالاً در اجرای واقعی مشکل‌ساز می‌شوند. همه‌ی موارد زیر **تست نشده‌اند** مگر اینکه صریحاً گفته شده باشد.

## ۱. کامپایل و وابستگی‌ها (ریسک بالا)
- **کد هنوز کامپایل نشده است.** ممکن است خطاهای کوچک Kotlin یا import جا افتاده باشد.
- **نسخه‌های وابستگی‌ها** بر اساس اطلاعات حدودی انتخاب شده‌اند: Kotlin 2.0.20، KSP 2.0.20-1.0.25، AGP 8.5.2، Compose BOM 2024.09.00، Room 2.6.1، Navigation 2.8.2. ممکن است Android Studio هشدار سازگاری بدهد.
- **`composeOptions.kotlinCompilerExtensionVersion = "1.5.14"`** با Kotlin 2.0 نیاز به Compose Compiler Plugin دارد. اگر خطای Compose compiler دیدی، باید پلاگین `org.jetbrains.kotlin.plugin.compose` را جای `kotlinCompilerExtensionVersion` بگذاری.
- **`Gradle Wrapper`** در ریپو نیست؛ Android Studio خودش می‌سازد.

## ۲. کدهای مشکوک که باید بازبینی شوند
- **`ProjectDetailScreen`**: در `val current = project ?: run { Text(...); return }` یک `return` داخل Composable است. ممکن است کامپایل شود ولی رفتار بهتر این است که با `if (project == null) { Text(...); return }` نوشته شود.
- **`WeeklyLogScreen` / `AddTaskDialog`**: `errorText = vm.error.collectAsStateWithLifecycle().value` داخل آرگومان فراخوانی است. کار می‌کند ولی بهتر است بیرون از فراخوانی گرفته شود.
- **`ProjectDetailViewModel`**: خطای افزودن هدف با `_error` مدیریت می‌شود. اگر کاربر بعد از خطا دوباره تلاش کند، خطای قبلی تا وقت پاک‌شدن باقی می‌ماند. `clearError()` هنوز از UI فراخوانی نمی‌شود.
- **`ProjectsViewModel.projects`** و **`ProjectDetailViewModel`** از `combine` و `stateIn` استفاده می‌کنند. `SharingStarted.WhileSubscribed` است، پس با رفتن به پس‌زمینه ممکن است داده دوباره لود شود.
- **`CalendarViewModel`**: آیتم‌های روتین را برای هر روز ماه در حافظه می‌سازد. برای ماه‌های عادی کافی است.
- **`AlarmReceiver`**: `notify(code, ...)` با `code` می‌تواند با اعلان‌های دیگر تداخل داشته باشد. فعلاً کدها متفاوت‌اند اما باید تست شود.
- **`TaskAlarmScheduler.routineCode`**: `routineId and 0x3FFFF` یعنی بیشتر از ۲۶۲ هزار روتین را پوشش می‌دهد. برای این اپ کافی است.

## ۳. آلارم و پس‌زمینه (ریسک بالا برای تجربه‌ی کاربر)
- **گوشی‌های شیائومی، هوآوی، سامسونگ و بعضی دیگر** آلارم‌های پس‌زمینه را محدود یا بسته می‌کنند. آلارم ممکن است نیاید حتی اگر کد درست باشد. کاربر باید «Battery optimization» را برای اپ روی «Unrestricted» بگذارد. بهتر است یک صفحه‌ی راهنما اضافه شود.
- **`SCHEDULE_EXACT_ALARM`** در اندروید ۱۴ به‌صورت پیش‌فرض رد می‌شود و کاربر باید از تنظیمات اجازه بدهد. بنر بالای صفحه این را نشان می‌دهد، ولی هنوز تست نشده است.
- **`BootReceiver`** با `goAsync()` و `CoroutineScope` ساخته شده. برای کارهای طولانی‌تر از چند ثانیه ممکن است سیستم متوقفش کند.
- **آلارم روتین** بعد از هر اجرا خودش نوبت بعد را ثبت می‌کند. اگر گوشی خاموش باشد یا اپ بسته شده باشد، نوبت بعد ممکن است از دست برود تا وقتی بوت یا آپدیت شود. این باید در تست دستی بررسی شود.
- **کاربر اجازه‌ی نوتیفیکیشن را رد کند** آلارم‌ها بی‌صدا ساکت می‌شوند. فعلاً پیام هشداری برای این حالت نداریم.

## ۴. دیتابیس و مهاجرت
- نسخه‌ی دیتابیس ۴ است و از `fallbackToDestructiveMigration()` استفاده می‌شود. **یعنی هر تغییر ساختار بعدی، داده‌ی کاربر را پاک می‌کند.** قبل از انتشار عمومی باید `Migration` نوشته شود.
- **هیچ تستی روی DAOها وجود ندارد** (تست instrumented). کوئری‌ها مثل `observeRange` و `upcomingUndone` هنوز تست نشده‌اند.
- **`ForeignKey` با `SET_NULL`** روی `tasks.projectId` و `CASCADE` روی `goals` و `routine_completions` تنظیم شده. Room به‌صورت پیش‌فرض کلیدهای خارجی را فعال می‌کند ولی باید تست شود.

## ۵. محدودیت‌های عملکردی و منطقی
- **ویرایش تسک و روتین وجود ندارد.** روتین فقط قابل ساخت و حذف است.
- **هفته‌ی گزارش فقط جاری است.** نمی‌شود گزارش هفته‌های قبل را از UI ساخت (در مدل داده امکانش هست).
- **تاریخ میلادی است.** برای کاربر ایرانی تاریخ شمسی انتظار می‌رود.
- **`WeeklyReport`** فقط تسک‌ها و روتین‌ها را می‌شمارد. اهداف پروژه در نمره‌ی هفته حساب نمی‌شوند.
- **نمره‌ی هفته** بدون داده (`percent == null`) ثبت می‌شود و نمره‌ای ندارد.
- **تیک زدن روتین** فقط برای همان روز است؛ اگر کاربر فراموش کند، آن روز ثبت نمی‌شود.
- **منطق زمان‌بندی تسک** با `dueAt` و `weekStart` است. اگر کاربر ساعت یا منطقه‌ی زمانی گوشی را عوض کند، ممکن است آلارم‌ها اشتباه شوند.

## ۶. رابط کاربری
- **آیکون‌ها** استفاده نشده‌اند؛ ناوبری پایین فقط متن دارد.
- **حالت تاریک** با `isSystemInDarkTheme` کار می‌کند ولی طراحی رنگ‌ها بررسی نشده.
- **حالت خالی** در بعضی صفحه‌ها متن ساده دارد و پیام راهنما کم است.
- **دکمه‌های حذف** بدون تأیید هستند؛ حذف پروژه یا روتین خطرناک است.
- **نوار پایین** در صفحه‌ی جزئیات پروژه مخفی می‌شود؛ دکمه‌ی بازگشت از TopBar نیست بلکه یک دکمه‌ی متنی داخل صفحه است.

## ۷. تست‌ها
- **تست‌های واحد:** `ProgressCalculatorTest`، `WeekUtilsTest`، `RoutineUtilsTest`، `WeeklyReportTest`، `RequestCodeTest`. هیچ‌کدام اجرا نشده‌اند.
- **تست‌های UI و instrumented:** وجود ندارد.
- **تست‌های بازنشانی آلارم:** فقط روی گوشی واقعی ممکن است.

## ۸. امنیت و حریم خصوصی
- همه‌ی داده‌ها محلی هستند و به سرور ارسال نمی‌شوند.
- `allowBackup="true"` در مانیفست است؛ یعنی داده‌ها ممکن است در بک‌آپ گوگل ذخیره شوند. اگر حریم خصوصی مهم است، باید `false` شود یا قوانین بک‌آپ تعریف شود.
- مجوزهای استفاده‌شده: نوتیفیکیشن، آلارم دقیق، دریافت بوت.

## ۹. فایل‌های ناقص یا موقت
- در محیط تولید کد یک فایل تست اضافی روی مسیر `main` ساخته شد (`domain/ProgressCalculatorTest.kt`). این فایل **روی دستگاه کپی نشده** و نباید وجود داشته باشد. اگر در Android Studio دیدی، آن را حذف کن.
